# Piano: rifacimento completo di `index.html` come "coach giornaliero + spunta"

## 🎯 Principio guida
App = **coach** (ti dice cosa fare oggi) + **tracking leggero** (spunta "✓ fatto" per esercizio). Uso esclusivamente mobile, durante l'allenamento. Zero input numerici da ridigitare.

## 📦 Modello dati (3 strati netti, separati)

```js
EXERCISES  // INALTERATO — 32 esercizi, 6 prop ciascuno (asset riusabile)
WEEK_PLAN  // NUOVO (rimpiazza SCHEDULE) — template Lun→Dom ricorrente
LOG        // NUOVO formato — spunta per-data, chiave localStorage "wlog"
steps_history  // INALTERATO — { dateISO: number }
```

**`WEEK_PLAN`** = template settimanale ricorrente (non per-data). Chiavi = nomi giorno italiani abbreviati. Facilissimo da editare (7 righe). Scelta motivata: 5 allenamenti fissi + 2 riposi, stessi esercizi che si ripetono ogni settimana; il LOG resta per-data quindi sai comunque "ho allenato Lun 27/6".
```js
const WEEK_PLAN = {
  "Lun": ["floor_press","push_ups","decline_push_ups","one_arm_row","bent_over_row","superman","crunches","plank"],
  "Mar": ["overhead_press","lateral_raises","rear_delt_flyes","bicep_curl","hammer_curl","chair_dips","overhead_extension"],
  "Mer": null,  // RIPOSO
  "Gio": ["floor_flyes","incline_push_ups","bulgarian_split_squat","goblet_squat","glute_bridge","sumo_squat","russian_twists","leg_raises"],
  "Ven": ["pullover","one_arm_row","concentration_curl","alternating_curl","cross_body_curl","tricep_kickback","skullcrusher"],
  "Sab": ["front_raises","overhead_press","chair_step_ups","frog_glute_bridge","plank","leg_raises"],
  "Dom": null   // RIPOSO
};
```
*(Contenuto provvisorio, dichiarato editabile dall'utente. L'architettura è indipendente dal contenuto.)*

**`LOG`** = `{ "2026-07-27": { "floor_press": true, "push_ups": true, ... }, ... }`. Chiave localStorage **`wlog`** (NUOVA, per evitare conflitti con la vecchia `workout_log` dal formato incompatibile `{sets:[...]}`). Vecchio `workout_log` cloud/local diventa orfano inoffensivo (l'app non lo legge più); `steps_history` continua a funzionare invariato.

## 🔄 Sync cloud Supabase — CONSERVATA integralmente
Tutto il blocco sync è solido, lo riutilizzo così com'è con una sola estensione:
- Mantengo: `SB_URL`, `SB_KEY`, `SYNC_CODE`, `SB_HEADERS`, `cloudFetch`, `cloudPull`, `cloudPush`, `scheduleCloudPush`, `rerenderCurrent`, `toISO`, busy-lock, debounce 800ms, pull intelligente (non disturba se input in focus), `setInterval` 20s, `visibilitychange`.
- Estendo: `localData()`/`applyData()` includono anche `wlog`; `mergeData()` fa merge non distruttivo anche su `wlog` (per-data per-exercise, come già fa su `workout_log`).

## 🔁 Funzioni JS

**Mantengo (sync + DB):** tutta la sync layer, `toISO`, `renderExerciseDatabase`/`filterExercises`/`toggleDbDescription`, `saveSteps`/`editSteps`/`refreshStepsSection`, `switchTab`, `drawBarChart`.

**Riscrivo:**
- `renderDayButtons()` — invariata a livello di logica (mostra settimana corrente), click → `selectDate(iso)`.
- `selectDate(iso)` — semplificata: deriva il nome giorno da `iso`, legge `WEEK_PLAN[weekday]`, renderizza header + card con checkbox. Se `WEEK_PLAN[weekday] === null` → layout riposo (come oggi).
- `generateWorkoutCard(id, iso, done)` — nuova card con checkbox (niente input).
- `toggleDone(exerciseId)` — toggle `LOG[iso][exerciseId]`, refresh visivo card + progress header, `scheduleCloudPush()`.
- `switchStatsPeriod(period)` — snellita (aderenza + passi).

**Rimuovo (codice morto/confuso):** `saveExerciseLog`, `saveAllExercises` + bottone "💾 Salva allenamento", `updateExerciseProgress`, `addSetInput`, tutti gli input serie/rip, `SCHEDULE`, vecchia lettura `workout_log`. Unifico le due `toggleDescription` gemelle in una.
